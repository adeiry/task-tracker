# Task Tracker Architecture

## 1. What the app does

Task Tracker is a learning-project application for creating, viewing, filtering, updating, moving, and deleting tasks. It consists of a FastAPI REST API and a self-contained vanilla HTML/CSS/JavaScript Kanban board with `ToDo`, `InProgress`, and `Done` columns.

## 2. Data model

The only implemented entity is **Task**:

- `id`: UUID4 string generated by the storage layer.
- `title`: required, trimmed, nonblank, maximum 200 characters.
- `description`: optional text; stored as an empty string by default.
- `status`: `ToDo`, `InProgress`, or `Done`; defaults to `ToDo`.
- `priority`: `Low`, `Medium`, or `High`; defaults to `Medium`.
- `assignee`: optional string.
- `due_date`: optional date.
- `tags`: trimmed strings, deduplicated case-insensitively; defaults to an empty list.
- `created_at`, `updated_at`: UTC timestamps generated by the storage layer.

`TaskCreate`, `TaskUpdate`, and `TaskResponse` provide separate request and response models. There are no implemented user, comment, project, or persistence entities.

## 3. Request flow

When a user creates a task, the frontend sends JSON to `POST /tasks`. FastAPI parses the request into `TaskCreate`, and Pydantic validates enums, the title, tags, dates, and unknown fields. If validation succeeds, the route handler calls `storage.add_task()`. The storage layer generates a UUID and UTC timestamps, creates a `TaskResponse`, and inserts it into a module-level dictionary keyed by task ID. FastAPI serializes the stored task and returns HTTP 201. Invalid input produces an automatic HTTP 422 response.

## 4. Key files

- `app/main.py` — Creates the FastAPI application, configures CORS, and defines health and task CRUD routes.
- `app/models.py` — Defines task request/response models, enums, defaults, and field validation.
- `app/storage.py` — Implements the in-memory dictionary and task CRUD/filtering operations.
- `app/business_rules.py` — Implements allowed status transitions, overdue detection, and normalized tag matching.
- `frontend/index.html` — Contains the complete Kanban interface and its API client logic.
- `tests/test_tasks.py` — Exercises task API creation, retrieval, filtering, updates, deletion, and validation.
- `tests/conftest.py` — Provides shared pytest setup and fixtures.
- `requirements.txt` — Pins the Python runtime and test dependencies.
- `Dockerfile` — Builds the Python 3.11 API image and runs Uvicorn as a non-root user.
- `README.md` — Documents setup, operation, project structure, and known limitations.

## 5. Conventions

- **Validation:** Pydantic models reject unknown fields. Titles and tags are trimmed; blank values are rejected where required. Tags use case-insensitive deduplication while preserving the first spelling.
- **Storage:** Tasks live in a process-local dictionary and disappear when the API restarts. IDs are UUID4 strings; timestamps use UTC.
- **Business rules:** Allowed status changes are `ToDo → InProgress`, `InProgress → Done`, and `Done → InProgress`. Other transitions, including same-status updates, return HTTP 422. A task is overdue when its due date is before the current local date and it is not `Done`.
- **Error handling:** Missing tasks return HTTP 404. Request/model validation and invalid status transitions return HTTP 422, although their response-detail shapes differ. Successful deletion returns HTTP 204.
- **Frontend/backend interaction:** The browser calls `http://localhost:8000` with `fetch`. The frontend loads tasks through the REST API and uses `POST`, `PATCH`, and `DELETE` for changes. CORS currently permits every origin.

## 6. Not visible or assumptions

No database, authentication, authorization, deployment platform, frontend build system, router/service implementation, or durable persistence is visible. The `app/api`, `app/repositories`, and `app/services` packages are placeholders, not active architectural layers. Task list ordering follows dictionary insertion order in the current implementation but is not an explicit contract. Runtime behavior and test results were not verified for this document.
